# 文件安全工具

一个用于本地文件与文本加解密、文件哈希校验的  Electron 桌面客户端 和 uTools 插件。数据处理在本机完成，不会上传到网络。

## 功能

| 功能 | 说明 |
| --- | --- |
| 文件加解密 | 支持单个或串行批量处理、真实任务取消、密码或 X25519 公钥保护，文件内容使用 AES-256-GCM 流式加密 |
| 密码修改 | 校验 FENC 协议头和当前密码后，仅更新密码元数据并重新包装 DEK，无需重新加密文件内容 |
| 文本加解密 | 将 UTF-8 文本加密为 Base64，也可将 Base64 密文还原为文本 |
| 文件校验 | 一次选择多个文件并计算 MD5、SHA-1、SHA-256；单文件自动计算并使用卡片展示 |
| 密码辅助 | 可生成安全随机密码，或使用原文件完整 SHA-256 快速填充密码 |
| 密钥管理 | 生成或导入 X25519 身份密钥，维护联系人公钥并导出 PEM 备份 |
| 加密历史 | 可选记录文件路径、密码或接收方公钥指纹和时间 |
| 加密设置 | 文件与文本设置独立管理，可分别调整压缩和密钥派生参数；文件组另含输出后缀与历史开关 |

## 安装与运行

源码开发需要 Node.js 20 或更高版本和 npm 10。使用 uTools 版本时还需要安装 [uTools](https://www.u.tools/)。

```bash
npm install
npm run dev:utools
```

开发服务器启动后，在 uTools 开发者工具中加载 `dist/plugin.json`。清单中的开发地址已配置为 `http://localhost:5173`。

独立 Electron 客户端开发：

```bash
npm run dev:electron
```

构建正式资源：

```bash
npm run build:utools
npm run build:electron
npm run dist:electron
```

uTools 产物位于 `dist/utools`，Electron 构建产物位于 `dist/electron`，Windows 安装包位于 `release`。

> 直接在普通浏览器中打开开发页面只能预览界面。完整功能需要 Electron preload 环境 或 uTools preload。

## 文件加解密

“文件加密”菜单下包含“单个处理”和“批量处理”。单个处理用于单独选择输出文件名；批量处理会为每个输入文件生成独立的 FENC 加密包或明文文件。

### 加密文件

1. 进入“文件加密”，选择“加密文件”。
2. 选择需要加密的文件。
3. 选择“密码”或“接收方公钥”。密码方式输入密码；公钥方式上传或粘贴 X25519 SPKI PEM 公钥。
4. 确认输出位置。默认在原文件名后添加设置中的后缀（默认为 `.enc`），如果文件已存在会自动追加序号。
5. 点击“开始加密”，完成后可在系统文件管理器中定位结果。

插件不会删除或覆盖原文件。请确认加密结果可正常解密后，再自行处理原文件。

### 解密文件

1. 切换到“解密文件”。
2. 选择加密文件。插件会自动识别密码或公钥方式，并显示密码框或 X25519 私钥输入框。
3. 确认输出位置后开始解密。

解密所需的算法、压缩方式和原文件后缀已经包含在密文中，无需手动选择。即使加密包由 `report.txt.enc` 改名为 `report.enc`，默认解密名称仍会恢复为 `report.txt`。密码、私钥或私钥保护密码错误，以及文件损坏时，解密会失败且不会保留不完整的输出文件。

### 批量处理

1. 进入“文件加密 > 批量处理”，选择批量加密或批量解密。
2. 选择或追加多个文件，并选择在原文件目录输出或指定统一输出目录。
3. 输入整批共用的密码或密钥凭据后开始处理。

批量任务按文件顺序串行执行，整体进度按输入文件字节数汇总，单个文件失败不会中断后续文件。输出可放回各原文件目录，也可统一放入指定目录；已有文件和同批次重名会自动避让。批量解密不能在同一次任务中混合密码包和公钥包，公钥包还必须属于同一接收方。取消任务会通过底层 `AbortSignal` 中止正在处理的流、删除不完整输出，并将尚未开始的项目标记为已取消；完成后可以重试失败或取消的项目。

### 准备 X25519 密钥

公钥使用 SPKI PEM，私钥使用 PKCS#8 PEM。可以通过 OpenSSL 生成带密码保护的私钥并导出公钥：

```bash
openssl genpkey -algorithm X25519 -aes-256-cbc -out private.pem
openssl pkey -in private.pem -pubout -out public.pem
```

只把 `public.pem` 发送给对方。`private.pem` 及其保护密码必须由接收方独立保存，丢失后无法恢复对应密文。

也可以在“密钥管理”中直接生成密钥对、导入现有私钥或保存联系人公钥。生成和导入的私钥会转换为带密码保护的 PKCS#8 PEM，并存放在 uTools `dbCryptoStorage`；保护密码不会保存。文件加密可以直接选择已保存公钥，文件解密会按接收方指纹自动匹配本机私钥。

## 文本加解密

文本加密会先把输入转换为 UTF-8 字节，再使用与文件相同的协议加密，最终输出 Base64 文本。

- 加密时输入原文和密码，结果可复制或下载为 TXT 文件。
- 解密时输入 Base64 密文和密码，结果可复制或下载。
- “上传文本”仅接受 UTF-8 TXT 文件。
- 下载文件名会包含原文 MD5 的前 16 位，便于区分结果。

## 修改加密包密码

进入“密码修改”，选择一个密码方式的 FENC 加密包并填写当前密码、新密码和确认密码。成功后仅更新密码配置和密钥包装数据，文件 payload 不会重新加密。公钥加密包不支持修改密码。

如果“记录加密历史”已开启，密码修改成功后会记录加密包路径、新密码、修改时间和“密码修改”类型。修改操作会原位更新文件，重要文件仍建议保留独立备份。

## 文件哈希校验

进入“文件校验”后选择一个或多个文件：

- 只选择一个文件时会立即计算，并以卡片展示 MD5、SHA-1 和 SHA-256。
- 选择多个文件时可统一计算并在表格中对比。
- 每个哈希值都可以复制。
- SHA-256 相同的文件会显示“相同”标记。

哈希只能用于完整性比对，不能代替数字签名，也不能证明文件来源可信。

## 加密设置

点击侧边栏底部的设置按钮会从左侧打开设置抽屉。文件和文本配置使用折叠分组独立管理：

- 文件加密设置：压缩方式、密钥派生强度、加密文件后缀和加密历史开关。
- 文本加密设置：独立的压缩方式与密钥派生强度，默认不压缩。

加密文件后缀默认为 `enc`，支持 1 至 8 位英文和数字，首位必须为英文字母。文件和文本设置互不影响。

“重置”会在二次确认后清空加密历史、非对称密钥、当前设置以及本插件的本地缓存，然后刷新页面。该操作无法撤销。

## 密码与历史安全

- 密码方式每次生成独立的 24 字节 scrypt salt；公钥方式每次生成独立的 32 字节 HKDF salt。两种方式都会生成独立的 32 字节数据密钥以及随机 nonce/IV。
- 密码通过 scrypt 派生密钥加密密钥（KEK），KEK 只负责包装随机数据密钥（DEK），不会直接加密文件内容。
- 公钥方式为每个文件生成临时 X25519 密钥，通过 ECDH 和 HKDF-SHA-256 派生 KEK，再使用 AES-256-GCM 包装 DEK。
- FENC v1 使用可变长度配置区：密码包保存 scrypt 档位和 salt，公钥包保存接收方指纹、临时公钥和 HKDF salt，两者末尾均保存经过认证的原文件后缀，不为另一种密钥保护方式预留空白字段。
- 压缩后的内容使用分块 AES-GCM 认证加密，可检测错误密码、内容篡改、块截断和块顺序异常。
- 忘记密码后无法从密文中恢复密码。使用随机密码时，请在安全位置单独保存。
- 公钥方式无法替代数字签名，也不能证明发送者身份；首次交换公钥时应通过独立渠道核对 SHA-256 指纹。
- “使用原文件 SHA-256”便于复现密码，但任何持有原文件的人都能得到相同密码，因此不适合需要强保密性的场景。
- 加密历史包含可恢复的密码，并保存在 uTools 的 `dbCryptoStorage` 加密存储中。不需要此功能时建议关闭历史开关，或在使用后及时清空。
- 压缩有时会泄露少量数据特征。对已经压缩的文件或高敏感场景，可选择“不压缩”。
